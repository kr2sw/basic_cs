# 39: OTA — Over-the-Air Firmware Update Concepts

## 개요

펌웨어를 업데이트하기 위해 케이블로 연결할 필요 없이, **네트워크를 통해 원격으로** 갱신하는 것을 OTA(Over-The-Air) 업데이트라고 합니다. 산업·가정용 IoT에서 수백 대의 기기를 직접 만지지 않고 업데이트하는 핵심 기술입니다. 이번 레슨에서는 **개념과 안전한 업데이트 설계**를 배우고, HTTP 기반의 간단한 OTA 메커니즘을 구현합니다.

## OTA의 기본 흐름

```
서버(펌웨어 호스팅) ── HTTP GET ──► ESP32
                                   1. 현재 버전 확인
                                   2. 새 펌웨어 다운로드
                                   3. 검증(체크섬/서명)
                                   4. 플래시에 기록
                                   5. 재부팅 → 새 펌웨어 실행
```

## 이중 파티션 (A/B 슬롯)

업데이트 중 전원이 끊기면 펌웨어가 손상됩니다. ESP32는 **OTA 파티션**을 두어 안전하게 전환합니다.

- 현재 실행 중인 파티션(A)을 보존한 채 B에 새 펌웨어 기록
- 검증 성공 시 부팅 파티션을 B로 전환
- 실패 시 A로 롤백

## 펌웨어 검증

다운로드한 펌웨어가 손상되었는지 **체크섬**으로 확인합니다.

```python
import hashlib
digest = hashlib.sha256(firmware).hexdigest()
if digest != expected_hash:   # 서버가 전달한 해시와 비교
    print("검증 실패 — 적용 취소")
```

보안을 높이려면 35장에서 배운 서명 검증을 추가합니다.

## 안전한 부팅 플래그

재부팅 직후 새 펌웨어가 정상 동작하는지 확인하고, 아니면 이전 버전으로 복귀합니다.

```python
# 재부팅 후 30초 안에 "정상 동작" 보고가 없으면 롤백
import machine
machine.rtc_mem_write(0, 1)   # 부팅 시도 횟수 기록
```

## 실행/업로드 방법

> 실제 OTA 플래시 기록은 `esptool`/`parttool`과 파티션 테이블 설정이 필요하므로, 이 레슨에서는 **개념 검증용 시뮬레이션** 코드를 제공합니다.

1. **Thonny IDE**: `MP/39-ota/main.py`를 열어 실행(F5).
2. 서버 역할은 PC에서 간단한 HTTP 파일 서버로 대체:
   ```bash
   python -m http.server 8000
   ```
3. ESP32가 `firmware.bin`을 다운로드해 체크섬 검증까지 수행하는 것을 시리얼로 확인합니다. 실제 플래시 기록은 보드의 OTA 파티션 설정 후 가능합니다.

## 핵심 개념 요약

- OTA = 네트워크를 통한 원격 펌웨어 갱신
- A/B 파티션으로 업데이트 중 전원 차단에도 안전
- 체크섬/서명 검증으로 손상·위조 펌웨어 차단
- 부팅 플래그로 실패 시 이전 버전 롤백
